# 开发规范

本规范用于统一团队成员在代码、文档和模型文件中的基础风格。若某个子项目已有更严格的规范，请以子项目规范为准，并在对应 README 中说明。

## 命名

| 对象 | 建议 |
| --- | --- |
| 目录 | 使用小写英文、数字和连字符，例如 `motor-driver/` |
| C/C++ 文件 | 使用小写英文和下划线，例如 `uart_protocol.c` |
| 类或结构体 | 使用清晰名词，避免 `Data1`、`InfoNew` 等临时名称 |
| 常量 | 使用大写字母和下划线，例如 `MAX_MOTOR_SPEED` |
| 模型文件 | 使用模块、零件、版本组合，例如 `chassis_side_plate_v1.step` |

## 代码格式

- 使用 4 个空格缩进，避免混用 Tab 和空格。
- 文件编码使用 UTF-8。
- 一个文件尽量只承担一个清晰职责。
- 公共接口应说明参数含义、单位、范围和返回值。
- 硬件相关代码应写明引脚、通信速率、供电条件和安全边界。

## 注释

好的注释解释“为什么这样做”和“有什么限制”，而不是重复代码本身。

推荐写明：

- 硬件限制、时序要求和异常情况。
- 控制参数的单位、来源和建议范围。
- 协议字段含义、字节序和校验方式。
- 临时方案的原因和后续替换计划。

## 文档

- 新增模块时，请同步补充 README。
- 文档中的命令、路径、参数和单位应可直接复现。
- 实验结论应包含硬件环境、软件版本、测试步骤和预期现象。

## 提交

- 单次提交尽量聚焦一个主题。
- 提交信息建议采用 `type(scope): summary` 格式。
- 不提交本地缓存、构建产物、临时日志和软件自动备份文件。
